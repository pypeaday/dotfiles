## Crossing the container boundary

- Host commands: `distrobox-host-exec <cmd>` runs on aurora (`notify-send` confirmed working).
- Open URLs in the host browser: `distrobox-host-exec xdg-open <url>` (e.g. MCP OAuth flows).
- `host-spawn` is also available; used to run host binaries (e.g. `npx` for the context7 MCP).
- **Absent CLI binaries in UbuntuDev**: `dig`/`nslookup` ARE installed (dnsutils, 2026-10-27, also in ansible `base-system`). (`sqlite3` was missing in earlier sessions but is now at `/usr/bin/sqlite3`; `python3`'s `sqlite3` module is the fallback if it disappears again.)
- Also absent: `whois`, `pdftotext`, `pandoc`, `pdfplumber`/`fitz`. Domain-ownership lookups → RDAP JSON: `curl -s https://rdap.verisign.com/<tld>/v1/domain/<domain>` for registrar/registration/expiry, then follow the registrar's `related` link for registrant/contact detail (worked against a Squarespace Domains II record). PDF text → `pypdf` IS installed; anything else missing → `uv run --with <pkg>` (`uv` at `~/.local/bin/uv`) — docx is a zip, `unzip -p f.docx word/document.xml | sed 's/<[^>]*>//g'` also works in a pinch.
- **`aws` CLI is absent too** — script AWS/R2 calls via `uv run --with boto3 python3 ...`. More generally `pip` is PEP-668-blocked and dep coverage is spotty (`boto3`/`yaml` happen to be installed, `cairosvg` isn't), so `uv run --with <pkg>` is the reliable pattern for ad-hoc Python work.
- **No audio in the container**: no `/dev/snd`, no pipewire socket — `arecord`/`pw-cli` are absent and browser `getUserMedia` always fails. Capture on the host instead: `distrobox-host-exec ffmpeg -f pulse -i <source>`; list mic sources with `distrobox-host-exec pactl list short sources` (the `default` source may be a dead monitor — pick a named `alsa_input.*`).
- **Signals don't cross host-spawn**: `SIGTERM` on a `distrobox-host-exec` child only kills the local proxy; the host process keeps running. Kill host procs by name: `distrobox-host-exec pkill -f <pattern>` — and check for leaked procs after long-running host commands.
- `/tmp` is shared container↔host — files a host-side ffmpeg writes land in the container's `/tmp` too.
- **nvim swap names differ by where the file was opened**: `~/.local/state/nvim/swap/` entries are the full path with `/`→`%`, but files opened inside the container get a `%home%nic%…` prefix while host-opened ones get `%var%home%nic%…` (Fedora's `/var/home`). Search by basename: `ls ~/.local/state/nvim/swap/ | grep <basename>` — a full-path `find` can miss the file. To inspect one without touching the real file: `nvim --clean --headless -r <file> -c 'w! /tmp/recovered.md' -c 'qa!'` then `diff` (plain `--headless` loads the user's plugins and dumps treesitter noise). Recovery prints `process STILL RUNNING: <pid>` when a live editor owns the swap — unsaved text then exists only in that process's memory, not in any file.
- `pgrep -f`/`pkill -f` self-match: the pattern string appears in the caller's own `bash -c` argv, so `pkill -f script.py` kills your own shell — and `pgrep -f | xargs kill` matches it too. Capture the PID at launch (`$!`, or the exec tool's `shell_id` → `kill_shell`) and kill that. Fallbacks: `pkill <procname>` without `-f`, or a self-excluding pattern like `[s]cript.py`.

## Agent runtime

- Sessions run inside herdr panes (`HERDR_ENV=1`; workspaces `websites`, `infra`, `homelab`). `herdr agent list` shows live agents; `/resume <session-id>` resumes a past session. To recover context from a prior Devin Desktop or CLI session in the same repo, query `~/.local/share/devin/cli/sessions.db` with `python3` (`sqlite3` module): `sessions(id, working_directory, title, last_activity_at)` indexes sessions and `message_nodes(session_id, node_id, chat_message)` holds JSON `{role, content}` messages. `created_at`/`last_activity_at` are Unix **seconds** — read them with `datetime(last_activity_at, 'unixepoch')`; dividing by 1000 (assuming ms) yields plausible-but-wrong `1970-01-2x` dates.
- To verify UI/terminal-app behavior (nvim keymaps, TUIs): `herdr pane split --current --direction right --cwd "$PWD" --no-focus`, then `pane run`/`send-keys`/`read` to drive and screenshot it. Headless nvim (`nvim --headless`) never fires `UIEnter`, so LazyVim's `VeryLazy` event (which restores `vim.opt.clipboard = "unnamedplus"` and loads `autocmds`/`keymaps`) and `LazyFile` plugins never run unless you trigger `nvim_exec_autocmds("UIEnter", ...)` manually; also `normal!` (with `!`) bypasses plugin keymaps (`y`/`p`) — use `nvim_feedkeys(..., "m", false)` to test remapped keys.
- Background subagents (`run_subagent` with `is_background: true`) cannot prompt for permissions — any tool not pre-approved in `config.json` (including `webfetch`) is auto-denied. Run web/research subagents in the foreground (`is_background: false`) or pre-approve the needed tools. `web_search` still works in background agents, and `python3 urllib` with a browser `User-Agent` header fetches platform docs fine when `webfetch` is unavailable.
- Processes started inside an `exec` shell die when that shell dies — a dev server (`uvicorn`) launched in a session was found dead later even though the command itself was fine (2026-10-23). For anything meant to outlive the turn, detach it: `setsid`/`nohup ... &`, `systemd-run --user`, or on the host via `distrobox-host-exec`.
- MCP servers configured: `git` (docker `mcp/git`), `context7` (npx via host-spawn), `cloudflare-docs`/`cloudflare-api` (remote HTTP), `forgejo` (docker `forgejo-mcp`, token `~/.local/share/devin/forgejo-token`), `twenty` (remote `crm.paynepride.com/mcp`), `drawio` (npx `@next-ai-drawio/mcp-server`), `signoz` (`~/.local/bin/signoz-mcp-server` against `http://ghost:3301`, token `~/.local/share/devin/signoz-token`).
