## Crossing the container boundary

- Host commands: `distrobox-host-exec <cmd>` runs on aurora (`notify-send` confirmed working).
- Open URLs in the host browser: `distrobox-host-exec xdg-open <url>` (e.g. MCP OAuth flows).
- `host-spawn` is also available; used to run host binaries (e.g. `npx` for the context7 MCP).
- **Absent CLI binaries in UbuntuDev**: `dig` is not installed — use `python3 -c "import socket ..."` / `getent hosts` / `distrobox-host-exec` for DNS checks. (`sqlite3` was missing in earlier sessions but is now at `/usr/bin/sqlite3`; `python3`'s `sqlite3` module is the fallback if it disappears again.)
- **No audio in the container**: no `/dev/snd`, no pipewire socket — `arecord`/`pw-cli` are absent and browser `getUserMedia` always fails. Capture on the host instead: `distrobox-host-exec ffmpeg -f pulse -i <source>`; list mic sources with `distrobox-host-exec pactl list short sources` (the `default` source may be a dead monitor — pick a named `alsa_input.*`).
- **Signals don't cross host-spawn**: `SIGTERM` on a `distrobox-host-exec` child only kills the local proxy; the host process keeps running. Kill host procs by name: `distrobox-host-exec pkill -f <pattern>` — and check for leaked procs after long-running host commands.
- `/tmp` is shared container↔host — files a host-side ffmpeg writes land in the container's `/tmp` too.
- `pgrep -f`/`pkill -f` self-match: the pattern string appears in the caller's own `bash -c` argv, so `pkill -f script.py` kills your own shell. Kill by PID (`pgrep -f` + `xargs kill`), or use a pattern that can't match itself (`[s]cript.py`).

## Agent runtime

- Sessions run inside herdr panes (`HERDR_ENV=1`; workspaces `websites`, `infra`, `homelab`). `herdr agent list` shows live agents; `/resume <session-id>` resumes a past session. To recover context from a prior Devin Desktop or CLI session in the same repo, query `~/.local/share/devin/cli/sessions.db` with `python3` (`sqlite3` module): `sessions(id, working_directory, title, last_activity_at)` indexes sessions and `message_nodes(session_id, node_id, chat_message)` holds JSON `{role, content}` messages.
- To verify UI/terminal-app behavior (nvim keymaps, TUIs): `herdr pane split --current --direction right --cwd "$PWD" --no-focus`, then `pane run`/`send-keys`/`read` to drive and screenshot it. Headless nvim (`nvim --headless`) never fires `UIEnter`, so LazyVim's `VeryLazy` event (which restores `vim.opt.clipboard = "unnamedplus"` and loads `autocmds`/`keymaps`) and `LazyFile` plugins never run unless you trigger `nvim_exec_autocmds("UIEnter", ...)` manually; also `normal!` (with `!`) bypasses plugin keymaps (`y`/`p`) — use `nvim_feedkeys(..., "m", false)` to test remapped keys.
- Background subagents (`run_subagent` with `is_background: true`) cannot prompt for permissions — any tool not pre-approved in `config.json` (including `webfetch`) is auto-denied. Run web/research subagents in the foreground (`is_background: false`) or pre-approve the needed tools.
- MCP servers configured: `git` (docker `mcp/git`), `context7` (npx via host-spawn), `cloudflare-docs`/`cloudflare-api` (remote HTTP), `forgejo` (docker `forgejo-mcp`, token `~/.local/share/devin/forgejo-token`), `twenty` (remote `crm.paynepride.com/mcp`), `drawio` (npx `@next-ai-drawio/mcp-server`), `signoz` (`~/.local/bin/signoz-mcp-server` against `http://ghost:3301`, token `~/.local/share/devin/signoz-token`).
- **SigNoz is self-hosted v0.64.0** — the `signoz_*dashboard*`/`get_org_overview` MCP tools 404 (they target a newer API surface). Use the MCP for data/log/trace/metric queries, and dashboards via the REST API directly: `GET http://ghost:3301/api/v1/dashboards` (and `/<uuid>`), token in `SIGNOZ_API_KEY`. Query API gotchas: a `query_range` request must include only the active query type's key — empty keys for the other types cause 404s — and `queryFormulas` is a top-level sibling of `builderQueries`, not nested inside it. `disabled: true` on a builder query means "hidden input for formulas", not "skipped".
- `SessionStart` hook reports pending mattpocock/skills upstream commits; `/update-skills` applies them.
- `Stop` hook pings the host desktop when an agent turn finishes inside a herdr pane.
- Headless runs: `devin -p "prompt"` for scheduled/scripted use.
- **Nightly dream pass** (`devin-dream.timer`, systemd --user, 03:30): `~/.config/devin/scripts/dream.sh` exports sessions newer than `~/.local/share/devin/cli/dream-watermark` from `sessions.db` into `~/dotfiles/.dream/inbox/<date>/`, then two headless `devin -p` stages run from `~`: `dream` distills proposals into `~/dotfiles/.dream/proposals/<date>/` (accept-edits), `dream-review` verifies them against repos and auto-applies doc updates (smart mode). Drift controls: applied edits commit as `dream: <date>` (`git log --grep dream` = audit trail), flagged items (AGENTS.md/scripts/skills) file/comment a Kanboard card on the Automated Tickets board (id 15), and Sundays run `dream-verify` — re-checks ~15 existing doc facts against reality and fixes stale ones. Dashboard at **https://dreams.paynepride.com** (nginx on ghost, stack `homelab-mono/compose/ghost/dreams`, webroot `/tank/encrypted/docker/dreams/www` — script rsyncs `dream-metrics.jsonl` + report markdown after each run). Logs: `~/.local/share/devin/cli/dream-logs/`. Note: `systemctl --user` here is the *container's* user manager — no `distrobox enter` needed in units.
